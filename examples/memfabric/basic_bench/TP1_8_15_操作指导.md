# TP1 1P1D：仅使用 137 的 8–15 号设备

日期：2026-10-25。适用于已有个人容器 `memfabric-d00896497-qwen3` 和其中的 Qwen3-8B 环境。以下启动、推理和 BM 检查命令会真实占卡，执行时须有当次设备使用授权。用户最新指定本轮截止北京时间 **16:15**，应从 **15:55** 起收尾归档并释放本轮进程；历史窗口不构成后续占用授权。

所有文件均放在容器私有目录 `/workspace/d00896497`。模型复用只读的 `/workspace/d00896497/models/Qwen3-8B`，不复制权重、不修改模型配置，也不安装、升级或下载依赖。

## 1. 设备布局与每个终端的准备

| 角色 | 物理设备 | `ASCEND_RT_VISIBLE_DEVICES` | 进程内设备编号 |
| --- | --- | --- | --- |
| P | 8 | `8` | 0 |
| D | 10 | `10` | 0 |
| LMCache service / BM owner | owner 为 12；service 还需访问 P/D | `8,9,10,11,12,13,14,15` | owner 为 4 |
| BM member | 14 | `14` | 0 |

本轮已通过 ACL 只读映射确认：完整后八设备可见时，local 0–7 对应 physical 8–15。不要把服务的 BM `device_id` 写成物理编号 12，也不要直接使用旧文件中默认的 device 0。service 必须能访问 P/D 的 IPC KV，因此保留完整后八设备可见。

每个新终端先进入**已有个人容器**，再加载现有环境。以下共同准备在每个终端执行一次；后面的 P、D、member 命令会按角色缩小可见范围。

```bash
docker exec -it memfabric-d00896497-qwen3 bash
source /workspace/d00896497/env.sh
cd /workspace/d00896497/src/LMCache-Ascend/examples/memfabric/basic_bench
export ASCEND_RT_VISIBLE_DEVICES=8,9,10,11,12,13,14,15
```

普通 A/B 共用：TP1、BF16、chunk/block size 128、L1 4 GiB、LRU、`max-model-len=4096`、`max-num-seqs=1`、`max-gpu-workers=2`，关闭 vLLM 本地前缀缓存。两组均使用 store `default`、prefetch `retain`；A 不配置 L2，B 配置 MemFabric。A/B 顺序运行，切换前人工结束自己这一组终端服务，确认本轮进程释放，再准备新的缓存和另一组服务。

## 2. A 组：LMCache L1 服务

在 service 终端完成共同准备后，直接执行：

```bash
lmcache server \
  --host 127.0.0.1 --port 25555 \
  --http-host 127.0.0.1 --http-port 28080 \
  --chunk-size 128 --l1-size-gb 4 --eviction-policy LRU \
  --supported-transfer-mode lmcache_driven --max-gpu-workers 2 \
  --prometheus-port 29090 \
  --l2-store-policy default --l2-prefetch-policy retain
```

A 组不运行 BM member。服务就绪后，分别在其他终端启动第 4 节的 P、D 和第 5 节的代理。

## 3. B 组：MemFabric 池与 LMCache 服务

先在本目录创建个人插件配置文件：

```bash

{
  "type": "plugin",
  "module_path": "lmcache_ascend.v1.distributed.memfabric_l2_adapter",
  "class_name": "MemFabricL2Adapter",
  "adapter_params": {
    "device_id": 4,
    "world_size": 2,
    "pool_gb": 4,
    "storage_rank": 1,
    "slot_size_mb": 32,
    "store_url": "tcp://127.0.0.1:28580"
  }
}
JSON
```

service 终端使用完整后八设备可见，启动下列命令；等待 member 时暂未就绪属于预期。在 90 秒内于另一个终端启动后面的 member 命令。

```bash
lmcache server \
  --host 127.0.0.1 --port 25555 \
  --http-host 127.0.0.1 --http-port 28080 \
  --chunk-size 128 --l1-size-gb 4 --eviction-policy LRU \
  --supported-transfer-mode lmcache_driven --max-gpu-workers 2 \

  --l2-store-policy default --l2-prefetch-policy retain \
  --l2-adapter "$(cat l2_tp1_8_15.json)"
```

member 终端完成共同准备后执行：

```bash
export ASCEND_RT_VISIBLE_DEVICES=14
python ../pool_member.py \
  --device 0 --rank 1 --world-size 2 --pool-gb 4 \
  --store-url tcp://127.0.0.1:28580
```

两个 rank 各分配 4 GiB DRAM；对象只存 storage rank 1。TP1/chunk128 对象约 18 MiB，32 MiB 槽下有效 KV 容量约 2.25 GiB，不能把两个 rank 的内存相加称为可用对象池。等待 service 与 member 就绪，再启动 P/D。
